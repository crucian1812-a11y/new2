### Колено на животе — главное, что стоит помнить

- Факт `near` в `hold` мерит **только вдоль мата**, высоту не видит. Поэтому
  у KNEE_ON_BELLY добавлены `below`: голень ≤ 0.46, стопа ≤ 0.34, опорная
  стопа ≤ 0.145, плюс `above` для голени над опорной стопой.
- Причина висящей ноги была в **тазе**: он был развёрнут так, что живот
  нижнего оказывался за бедром верхнего. Опустить одну ногу — бедро
  разгибается назад на 159° и сводится на 76°, и в переходе
  `CLINCH>TURTLE_X` оно прокручивалось в тазу. Судьи поз этого не видят
  (`hinge-check` меряет у бедра только поворот).
- Решение: таз повёрнут на Δ, позвоночник и бёдра — на Δ⁻¹ (корпус и ноги
  на месте в мире); Δ найден перебором с ценой анатомии бедра и корпуса;
  поворот поделён между spine и chest. WORK — тем же Δ.
- 10 переходов через KOB перерешены (`arc-all --only … --fresh`), три —
  с `ARC_LIMB=1`. `CLINCH>TURTLE_X` переведён на `SIDE_ENTRY@early`
  (21 см в начале, но без вывернутых суставов) — теперь он верх списка
  работ `blend-check`.
- Инструменты: `arc-solve` даёт сгибу 0.5° допуска ниже черты 155 и
  называет правило отказа; `arc-all` пробрасывает `--fresh`.

## Что дальше: Harmony4D

Решено попробовать **Harmony4D** (CMU, NeurIPS 2024): 3D-позы двух людей в
контакте с 20+ камер, есть категория `02_grappling`.

**Блокер: сеть.** Данные на `huggingface.co`, а он закрыт сетевой
политикой окружения (403 от прокси). GitHub доступен — код датасета
читается. Чтобы открыть:

1. На claude.ai/code — кнопка с облаком и именем окружения **над полем
   ввода** → навести на окружение → **шестерёнка**.
2. **Network access** → **Custom**, в **Allowed domains**:
   `huggingface.co`, `*.huggingface.co`, `*.hf.co`; галочка
   **Also include default list of common package managers**.
3. **Save changes**. Существующие сессии подхватывают за ~минуту.

Либо уровень **Full**. Если окружение общее для организации — меняет
владелец в админ-настройках (**Cloud environments**).

Проверка доступа:
`curl -s -o /dev/null -w '%{http_code}' https://huggingface.co/api/datasets/Jyun-Ting/Harmony4D`
(должно быть 200, сейчас 403/000).

**Что уже готово** — `bjj/tools/h4d.mjs`:

- Формат (по коду загрузчика, репозиторий `jyuntins/harmony4d`): на
  последовательность `processed_data/poses3d/00001.npy` …, в каждом —
  пикл словаря `{aria01, aria02}` → массив 133 точек COCO-WholeBody в
  метрах. SMPL не нужен (у него некоммерческая лицензия).
- `.npy` читается в Node без Python; вертикаль — по стоящим кадрам (иначе
  по лодыжкам), пол — 2-й процентиль самых низких точек, масштаб — по
  длине ног; направления костей из данных, длины наши.
- Мера: `node bjj/tools/h4d.mjs --roundtrip` — ноги 0.1 см, руки 2.2 см,
  голова 2.3 см (медианы). Синтетическая последовательность в чужой
  системе координат — 1.5 см по всем точкам пары.
- Запуск на данных: `node bjj/tools/h4d.mjs SEQ_DIR [from] [to] --every 30`
  печатает пару как блоки поз.

**План, когда будет доступ:**

1. Посмотреть листинг датасета: лежат ли позы отдельно от картинок
   (картинки — сотни ГБ). Скачать только `poses3d` для `02_grappling`.
   Проверить лицензию **данных** (MIT стоит на код).
2. Прогнать `h4d.mjs` по последовательностям, найти кадры, похожие на
   наши позиции (KNEE_ON_BELLY, MOUNT, SIDE_CONTROL, …).
3. Взять их как замысел позы и довести `pose-relax --bake-grips`, затем
   дуги — обычным циклом.
4. Мерило: распределения углов бедра/плеча/корпуса у живых людей в
   контакте и глубина взаимопроникновения — сверить с порогами наших
   судей.
