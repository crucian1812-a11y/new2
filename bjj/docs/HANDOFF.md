## 1. Что это

Браузерная игра про бразильское джиу-джитсу под телефон. Свой WebGL2 без единой
библиотеки и без шага сборки: ES-модули, `index.html` открывается напрямую.
Управление в стиле UFC — левый палец несёт базу, правый бросает и отменяет.

Вес того, что качает игрок: **455 КБ ассетов + 248 КБ кода**. Запас огромный.

## 2. Семь вещей, на которых всё держится

1. **Парные позы.** Каждый ключевой кадр в `src/game/poses.js` содержит **оба**
   скелета сразу и смещение между их тазами. Грэпплинг иначе не анимируется: два
   тела здесь — один шарнирный объект с двумя корнями. `A` и `B` — это роли, а не
   бойцы; `A` всегда тот, кто в лучшей позиции.
2. **Граф позиций.** `src/game/positions.js`: 15 позиций, 47 рёбер. Ребро
   принадлежит роли (сверху/снизу) и направлению свайпа, у каждого есть
   направление отмены — это вся защитная игра.
3. **Захваты через IK.** `grips` в позе говорят «эта рука держит вот эту точку на
   том», и после блёнда рука доводится двухкостным IK. Поэтому захват за лацкан
   остаётся на лацкане весь проход, а не только на двух ключевых кадрах.
4. **Дуги переходов.** `src/game/arcs.js` — решённая оффлайн поправка на каждый
   переход, обнуляющаяся на обоих концах. См. раздел 4.
5. **Замысел позиции.** `src/game/intent.js` + поле `hold` в позах: набор фактов,
   которые делают позицию собой, в форме, которую машина может проверить.
6. **Боец печётся из риггованного Mixamo.** `tools/bake-mixamo.mjs`. См. раздел 5.
7. **Марки клуба — вектор в коде.** `src/render/marks.js` + свой штриховой шрифт
   `src/render/glyphs.js`. Обе эмблемы («Арес» и Olavo Abreu BJJ) рисуются
   контурами и штрихами и растеризуются в один атлас 1024² на загрузке (~250 мс).
   На мате — миром, на кимоно — собственными UV бойца, поэтому нашивка пришита к
   ткани. Размещение живёт в `MAT_MARKS` и `GI_PATCHES` и оттуда же берётся
   шейдером через юниформы: у раскладки одно место, а не два.

## 3. Рабочий цикл: всё измеряется

Это главное методологическое решение проекта, и оно родилось из провала. Пятнадцать
парных поз были написаны набором углов в файл **без какой бы то ни было обратной
связи** о том, занимают ли два тела одно и то же место. Занимали — до 21 см.
Предплечья внутри черепов. Никто и ничто об этом не сообщало, и правки шли в свет,
в шейдеры, в камеру — то есть мимо.

Поэтому: **сначала измеритель, потом решатель, потом правка.**

```bash
node bjj/tools/verify.mjs              # всё сразу: линты + боец + 400 матчей, ~5 с
node bjj/tools/pose-check.mjs          # 15 поз: пересечения, мат, досягаемость, замысел
node bjj/tools/blend-check.mjs         # 43 перехода: худший момент в полёте
node bjj/tools/asset-check.mjs         # запечённый боец: веса, кости, размеры, материалы
node bjj/tools/sim-check.mjs 500       # баланс: чем кончаются матчи, ранжируются ли пояса
node bjj/tools/mark-check.mjs          # клубные марки: шрифт, атлас, разметка мата, нашивки
```

Решатели (пишут в исходники, запускать осознанно):

```bash
node bjj/tools/pose-relax.mjs --write             # позы
node bjj/tools/arc-solve.mjs --write              # дуги переходов (~40 мин на все)
node bjj/tools/arc-solve.mjs --only A>B --write   # одну; тёплый старт из arcs.js
node bjj/tools/via-pick.mjs --write               # через какую позу гнуть переход
```

Глаза (нужен `python3 -m http.server 8099` в корне репозитория):

```bash
node bjj/tools/sheet.mjs out           # по кадру на каждую позу, камерой из игры
node bjj/tools/angles.mjs MOUNT out    # одна поза с четырёх сторон, включая сверху
node bjj/tools/strip.mjs A B out       # переход покадрово
node bjj/tools/shot.mjs out.png --pose MOUNT --play 8
node bjj/tools/mark-check.mjs --dump out   # атлас марок + план мата сверху
```

**Вид сверху ловит то, что не ловит ничто другое** — например маунт, у которого оба
колена оказались с одной стороны от лежащего.

## 4. Как решаются позы и переходы

**Позы.** `pose-relax.mjs` — ограниченный поиск по всем углам и обеим корневым
позициям. Ценой служит: тела не внутри друг друга, всё ещё в контакте, на мате,
руки достают до захватов, ни одна рука не выпрямлена в замок, позиция остаётся
собой (`hold`), и как можно ближе к написанному. **Ограничение и есть суть**: 22
градуса на сустав, и на выходе та же поза, а не выдуманная.

Написанная поза — это замысел. Решатель делает её правдой.

**Переходы.** Слерп между двумя валидными клубками проходит через невалидные, и это
не чинится доработкой ни одного из концов. `arc-solve.mjs` ищет поправку из **двух
долей** (одна к началу блёнда, другая к концу, обе нулевые на концах): куда
растащить пару, насколько повернуть каждого, пара углов суставов. Порядок, в
котором это выяснялось, стоит знать:

| | худший момент |
|---|---|
| только растащить пару | 29 → 28 см |
| + повернуть и согнуть суставы | → 20 см |
| + две доли вместо одной | → 21 см, дальше уточняется тёплыми перезапусками |

Суставы, которые разрешено двигать, выбираются вопросом «что сейчас реально
сталкивается», и вопрос задаётся заново после каждого прохода: вытащив одну
конечность из тела, надёжно обнаруживаешь следующую.

Там, где конечность надо провести **вокруг** тела, а не растолкать, переход идёт
квадратичной кривой через третью позу из библиотеки (`VIAS`). Без ограничения на
то, насколько далеко пара расходится по дороге, все до единого выбирают СТОЙКУ —
она решает пересечения тем, что разводит бойцов на полметра.

## 5. Пекарь бойца

`tools/bake-mixamo.mjs`. Ничего не угадывается: скелет в файле, bind-матрица каждой
кости в файле как `TransformLink` её кластера, веса скиннинга в файле. Пекарь
сопоставляет 67 костей `mixamorig` с нашими 24 и переносит меш из их rest-позы в
нашу.

Две ловушки, каждая стоила бага:

- **Перенос по направлениям костей, а не по bind-матрицам.** Bind-матрица несёт ту
  ориентацию покоя, которую выбрал её автор, и авторы выбрали разные: у нашего
  персонажа кость стопы смотрит вдоль стопы, у нас — строго вниз. Оба рига согласны
  только в одном — **где суставы**. Туда же встаёт коэффициент длины кости.
- **Обратная bind-матрица оставляет вершину в единицах исходника** — в сантиметрах.
  Скормить это нашей матрице в метрах — меш оказывается в 33 метрах под полом.

Кимоно: рубашка и штаны персонажа перекрашиваются и служат корпусом, рукав — рука
снизу, выдавленная по нормалям с подгибом к коже. Пояс, полы и воротник
**обмеряются по куртке** (28 угловых секторов), и мерить надо **только туловище**:
риг стоит с опущенными руками, поэтому самая широкая вершина на уровне бёдер — это
рукав.

`tools/bake-fighter.mjs` — прежний путь для голого скульпта без скелета. Работает,
но каждый его этап — оценка поверх оценки. Оставлен как есть.

## 6. Грабли, за которые уже заплачено

Не наступать повторно:

- **Круглые капсулы на торсе врут.** Торс 21 см в ширину и 15 в глубину и сужается
  к шее. Круглая капсула радиуса 17.5 см ставит шар там, где горло, и рука,
  обвитая вокруг шеи, читается как 14 см проникновения. `collide.js` строит
  коническо-эллиптические сечения **из той же таблицы**, по которой строится меш.
- **Точки захвата должны лежать на поверхности**, а не на кости внутри руки.
  Захват за рукав был прописан в 3 см от кости предплечья, то есть внутри него.
- **Блик и контровой свет должны тонироваться альбедо.** Иначе чёрный пояс,
  повёрнутый в лоб к камере, вымывается до серого.
- **Обводка (вывернутая оболочка) — в экранных пикселях, не в метрах**, и только на
  геометрии толще самого наращивания. Волосы, ресницы и глазные яблоки — мимо.
- **Смена плана камеры — это склейка, а не наезд.** Плавный переход выглядит как
  бегущий оператор.
- **Кадрировать землю объективом, а не штативом.** Камера на высоте мата в двух
  метрах уже внутри чьих-то ног.
- **Решатель без ограничений найдёт не ту позицию.** «Не внутри друг друга»
  одинаково хорошо выполняется маунтом и боковым удержанием.
- **Свободная рука — это флаг.** Рука, которая ни за что не держится, остаётся там,
  где её оставили углы. В грэпплинге праздных рук не бывает.
- **Складывать мир через `abs()` ради симметрии — значит отзеркалить надписи.**
  Четыре угловые эмблемы на мате берутся переносом через `sign()`, а не
  отражением: у отражённой эмблемы текст задом наперёд.
- **Атлас лежит «по-гэлевски», снизу вверх.** Инструмент, который читает его как
  обычную картинку, промахивается ячейкой и рисует план чужого мата. Шейдер при
  этом прав — ошибся инструмент.
- **Тёмный текст на мате не читается: зона боя тёмно-синяя.** Печатный файл клуба
  (чёрным по белому) — единственное, что нельзя перенести один в один.
- **Белая нашивка на белом кимоно исчезает.** Чёрное кольцо у эмблемы аффилиации
  должно стоять ровно по краю диска — на мате это ничего не меняет, на ги это
  вся разница между нашивкой и пятном.
- **Подмена лица нарисованными чертами портит вылепленное лицо.** Где у меша есть
  настоящее лицо — шейдить и не трогать; рисовать глаза только там, где их нет.

## 8. Что дальше, по убыванию отдачи

1. **Второй и третий персонаж.** Сейчас на мате один и тот же человек в разных
   кимоно (`gpuB = gpuA` в `main.js`) — самый громкий оставшийся сигнал «это
   демка». Нужны файлы Mixamo **FBX → With Skin**, обычные одетые люди спортивного
   сложения. Пекарь определяет части меша по костям, а не по именам, — должно
   пройти без правок. Избегать доспехов, плащей, юбок.
2. ~~Разметка и герб на мате~~ и ~~нашивки на кимоно~~ — **сделано**, см. пункт 7
   раздела 2. Отменена и прежняя установка «придуманные марки»: игра делается для
   зала клуба «Арес», и на мате с кимоно стоит символика самого клуба и его
   аффилиации Olavo Abreu BJJ. Что можно доделать по мелочи: щиты вокруг мата и
   экран джамботрона сейчас всё ещё безымянные цветные панели — они уже читают
   тот же атлас, добавить туда надпись клуба стоит десяти строк.
3. **Движение внутри позиции — настоящий потолок.** Сейчас удержание это фотография
   с дыханием. Ассетами не чинится: парной грэпплинг-анимации в свободном доступе
   нет. Нужны 2–3 дополнительные парные позы на позицию, циклящиеся микро-петлёй.
4. Оставшиеся 16 переходов; звук (голос рефери, хлопки ги — единственное, где файлы
   лучше синтеза); визуальный язык усталости помимо полосок HUD.
