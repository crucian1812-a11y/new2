## 1. Что это

Браузерная игра про бразильское джиу-джитсу под телефон. Свой WebGL2 без единой
библиотеки и без шага сборки: ES-модули, `index.html` открывается напрямую.
Управление в стиле UFC — левый палец несёт базу, правый бросает и отменяет.

Вес того, что качает игрок: **455 КБ ассетов + 248 КБ кода**. Запас огромный.

## 2. Восемь вещей, на которых всё держится

1. **Парные позы.** Каждый ключевой кадр в `src/game/poses.js` содержит **оба**
   скелета сразу и смещение между их тазами. Грэпплинг иначе не анимируется: два
   тела здесь — один шарнирный объект с двумя корнями. `A` и `B` — это роли, а не
   бойцы; `A` всегда тот, кто в лучшей позиции.
2. **Граф позиций.** `src/game/positions.js`: 15 позиций, 47 рёбер. Ребро
   принадлежит роли (сверху/снизу) и направлению свайпа, у каждого есть
   направление отмены — это вся защитная игра.
3. **Захваты через IK.** `grips` в позе говорят «эта рука держит вот эту точку на
   том», и после блёнда рука доводится двухкостным IK. Поэтому захват за лацкан
   остаётся на лацкане весь проход, а не только на двух ключевых кадрах.
4. **Дуги переходов.** `src/game/arcs.js` — решённая оффлайн поправка на каждый
   переход, обнуляющаяся на обоих концах. См. раздел 4.
5. **Замысел позиции.** `src/game/intent.js` + поле `hold` в позах: набор фактов,
   которые делают позицию собой, в форме, которую машина может проверить.
   Вариант позиции (`variantOf`) объявляет только то, чем он вариант, и как
   выглядят двое; метку, очки, роль сверху, `hold` и захваты он **берёт у самой
   позиции**. Две копии всегда расходятся, а разошедшийся `hold` — ровно тот
   провал, ради которого он и заведён.
6. **Боец печётся из риггованного Mixamo.** `tools/bake-mixamo.mjs`. См. раздел 5.
7. **Марки клуба — вектор в коде.** `src/render/marks.js` + свой штриховой шрифт
   `src/render/glyphs.js`. Обе эмблемы («Арес» и Olavo Abreu BJJ) рисуются
   контурами и штрихами и растеризуются в один атлас 1024² на загрузке (~250 мс).
   На мате — миром, на кимоно — собственными UV бойца, поэтому нашивка пришита к
   ткани. Размещение живёт в `MAT_MARKS` и `GI_PATCHES` и оттуда же берётся
   шейдером через юниформы: у раскладки одно место, а не два.

8. **Звук — два слоя.** `src/core/audio.js`. Зал и каждый удар синтезируются;
   поверх, когда пак в `assets/audio` докачался (после первого касания, в
   фоне), тот же удар играет записью. Не загрузилось — игра звучит как раньше.
   Петли сводятся кроссфейдом: две из присланных не сходятся на шве.

## 3. Рабочий цикл: всё измеряется

Это главное методологическое решение проекта, и оно родилось из провала. Пятнадцать
парных поз были написаны набором углов в файл **без какой бы то ни было обратной
связи** о том, занимают ли два тела одно и то же место. Занимали — до 21 см.
Предплечья внутри черепов. Никто и ничто об этом не сообщало, и правки шли в свет,
в шейдеры, в камеру — то есть мимо.

Поэтому: **сначала измеритель, потом решатель, потом правка.**

```bash
node bjj/tools/verify.mjs              # всё сразу: линты + боец + 400 матчей, ~5 с
node bjj/tools/pose-check.mjs          # 35 поз: пересечения, мат, досягаемость, замысел
node bjj/tools/blend-check.mjs         # 43 перехода и 20 петель: худший момент в полёте
node bjj/tools/asset-check.mjs         # запечённый боец: веса, кости, размеры, материалы
node bjj/tools/sim-check.mjs 500       # баланс: чем кончаются матчи, ранжируются ли пояса
node bjj/tools/flow-check.mjs         # стык кадров: разрывы картинки, кольцо, простой
node bjj/tools/mark-check.mjs          # клубные марки: шрифт, атлас, разметка мата, нашивки
node bjj/tools/clip-check.mjs пак.glb  # присланный пак анимации (GLB или папка FBX)
node bjj/tools/audio-check.mjs         # присланный звук: декод, уровни, швы петель
node bjj/tools/scene-check.mjs зал.fbx # присланный зал: чем он лучше собственного
node bjj/tools/sound-check.mjs         # игра звучит, и её слышно над залом
node bjj/tools/net-check.mjs           # первая минута на 1.5 Мбит/с: кадр, байты, музыка
node bjj/tools/frame-check.mjs          # чего стоит кадр: вызовы, программы, униформы, треугольники
node bjj/tools/thumb.mjs --matches 3    # живой палец: попадания в такт, защита, что вышло
node bjj/tools/look-check.mjs           # сама картинка: контакт, складки, окклюзия, лицо
node bjj/tools/escape-check.mjs         # выход из захвата рукой с человеческой задержкой
node bjj/tools/human-check.mjs          # может ли человек выиграть: рука с задержкой, 400 матчей
node bjj/tools/tape-check.mjs           # разбор матча не врёт: очки, корзины, каждая строка
node bjj/tools/shake-check.mjs          # дрожь и рывки: где сустав был на соседнем кадре
node bjj/tools/camera-check.mjs        # видно ли приём: что попадает в кадр и что срезано
node bjj/tools/ring-check.mjs           # кольцо — это кнопки: попадание пальцем на семи экранах
node bjj/tools/tap-check.mjs            # и настоящий тап по кнопке доезжает до match.input
```

Прореживатель меша — `tools/decimate.mjs`, вызывается из `bake-mixamo --tris N`
и печатает, на сколько миллиметров сдвинулась поверхность. Схлопывание всегда на
**уже существующую** вершину, поэтому веса, UV, материал и окклюзия не
выдумываются; границы материалов и открытые края не трогаются.

`thumb.mjs` — единственный, который идёт минутами, а не секундами: он играет
матч в реальном времени, потому что вся его тема — человеческие задержки, а их
нельзя перемотать. `human-check.mjs` — его быстрая половина: та же опоздалость,
headless, тысяча матчей в минуту, и читает он только то, что рисует HUD. Пара
нужна целиком: первый отвечает «успевает ли рука», второй — «кто выигрывает из
двухсот». Пока второго не было, игра была непроходимой и никто из измерителей
этого не видел.

Решатели (пишут в исходники, запускать осознанно):

```bash
node bjj/tools/pose-relax.mjs --write             # позы
node bjj/tools/arc-solve.mjs --write              # дуги переходов (~40 мин на все)
node bjj/tools/arc-solve.mjs --only A>B --write   # одну; тёплый старт из arcs.js
node bjj/tools/via-pick.mjs --write               # через какую позу гнуть переход
```

Глаза (нужен `python3 -m http.server 8099` в корне репозитория):

```bash
node bjj/tools/sheet.mjs out           # по кадру на каждую позу, камерой из игры
node bjj/tools/angles.mjs MOUNT out    # одна поза с четырёх сторон, включая сверху
node bjj/tools/strip.mjs A B out       # переход покадрово
node bjj/tools/shot.mjs out.png --pose MOUNT --play 8
node bjj/tools/mark-check.mjs --dump out   # атлас марок + план мата сверху
```

**Вид сверху ловит то, что не ловит ничто другое** — например маунт, у которого оба
колена оказались с одной стороны от лежащего.

## 4. Как решаются позы и переходы

**Позы.** `pose-relax.mjs` — ограниченный поиск по всем углам и обеим корневым
позициям. Ценой служит: тела не внутри друг друга, всё ещё в контакте, на мате,
руки достают до захватов, ни одна рука не выпрямлена в замок, позиция остаётся
собой (`hold`), и как можно ближе к написанному. **Ограничение и есть суть**: 22
градуса на сустав, и на выходе та же поза, а не выдуманная.

Написанная поза — это замысел. Решатель делает её правдой.

**Переходы.** Слерп между двумя валидными клубками проходит через невалидные, и это
не чинится доработкой ни одного из концов. `arc-solve.mjs` ищет поправку из **двух
долей** (одна к началу блёнда, другая к концу, обе нулевые на концах): куда
растащить пару, насколько повернуть каждого, пара углов суставов. Порядок, в
котором это выяснялось, стоит знать:

| | худший момент |
|---|---|
| только растащить пару | 29 → 28 см |
| + повернуть и согнуть суставы | → 20 см |
| + две доли вместо одной | → 21 см, дальше уточняется тёплыми перезапусками |

Суставы, которые разрешено двигать, выбираются вопросом «что сейчас реально
сталкивается», и вопрос задаётся заново после каждого прохода: вытащив одну
конечность из тела, надёжно обнаруживаешь следующую.

Там, где конечность надо провести **вокруг** тела, а не растолкать, переход идёт
квадратичной кривой через третью позу из библиотеки (`VIAS`). Без ограничения на
то, насколько далеко пара расходится по дороге, все до единого выбирают СТОЙКУ —
она решает пересечения тем, что разводит бойцов на полметра.

## 5. Пекарь бойца

`tools/bake-mixamo.mjs`. Ничего не угадывается: скелет в файле, bind-матрица каждой
кости в файле как `TransformLink` её кластера, веса скиннинга в файле. Пекарь
сопоставляет 67 костей `mixamorig` с нашими 24 и переносит меш из их rest-позы в
нашу.

Две ловушки, каждая стоила бага:

- **Перенос по направлениям костей, а не по bind-матрицам.** Bind-матрица несёт ту
  ориентацию покоя, которую выбрал её автор, и авторы выбрали разные: у нашего
  персонажа кость стопы смотрит вдоль стопы, у нас — строго вниз. Оба рига согласны
  только в одном — **где суставы**. Туда же встаёт коэффициент длины кости.
- **Обратная bind-матрица оставляет вершину в единицах исходника** — в сантиметрах.
  Скормить это нашей матрице в метрах — меш оказывается в 33 метрах под полом.

Кимоно: рубашка и штаны персонажа перекрашиваются и служат корпусом, рукав — рука
снизу, выдавленная по нормалям с подгибом к коже. Пояс, полы и воротник
**обмеряются по куртке** (28 угловых секторов), и мерить надо **только туловище**:
риг стоит с опущенными руками, поэтому самая широкая вершина на уровне бёдер — это
рукав.

**Окклюзия печётся вместе с мешем** (`tools/ao.mjs`): 32 косинусных луча на
вершину по полусфере в четверть метра, сетка по треугольникам, спираль вместо
случайных чисел — один персонаж пёкся в один и тот же файл дважды. Байт на
вершину, **формат версии 2**; версия 1 читается по-прежнему и светится как
раньше, поэтому старый файл в чьём-нибудь кэше игру не ломает. Печётся в
bind-позе: подмышка, которая раскроется, останется такой же тёмной, какой была
закрытой, — для головы, ради которой это писалось, это точно.

Что оно даёт и чего не даёт — пункт 7 плана. Коротко: глазниц и подчелюстья в
затенении не было вовсе, а нарисованные в шейдере глаза и рот (материал 6) не
исполняются ни на одном бойце, которого грузит игра, — оба печены отсюда, а этот
пекарь настоящее лицо не трогает. У соперника нет и материала глаз: его глазные
яблоки приехали вваренными в меш тела двумя сферами по 449 вершин.

`tools/bake-fighter.mjs` — прежний путь для голого скульпта без скелета. Работает,
но каждый его этап — оценка поверх оценки. Оставлен как есть; материал 6 —
нарисованное лицо — бывает только у него.

## 6. Грабли, за которые уже заплачено

Не наступать повторно:

- **Круглые капсулы на торсе врут.** Торс 21 см в ширину и 15 в глубину и сужается
  к шее. Круглая капсула радиуса 17.5 см ставит шар там, где горло, и рука,
  обвитая вокруг шеи, читается как 14 см проникновения. `collide.js` строит
  коническо-эллиптические сечения **из той же таблицы**, по которой строится меш.
- **Точки захвата должны лежать на поверхности**, а не на кости внутри руки.
  Захват за рукав был прописан в 3 см от кости предплечья, то есть внутри него.
- **Блик и контровой свет должны тонироваться альбедо.** Иначе чёрный пояс,
  повёрнутый в лоб к камере, вымывается до серого.
- **Обводка (вывернутая оболочка) — в экранных пикселях, не в метрах**, и только на
  геометрии толще самого наращивания. Волосы, ресницы и глазные яблоки — мимо.
- **Смена плана камеры — это склейка, а не наезд.** Плавный переход выглядит как
  бегущий оператор.
- **Кадрировать землю объективом, а не штативом.** Камера на высоте мата в двух
  метрах уже внутри чьих-то ног.
- **Решатель без ограничений найдёт не ту позицию.** «Не внутри друг друга»
  одинаково хорошо выполняется маунтом и боковым удержанием.
- **Свободная рука — это флаг.** Рука, которая ни за что не держится, остаётся там,
  где её оставили углы. В грэпплинге праздных рук не бывает.
- **ИИ тратит всё, что у него есть.** Оба бойца лежали на нуле выносливости с
  тридцатой секунды и весь матч: единственным тормозом было «не хватает сил».
  Поднять восстановление не помогает — прибавку тут же тратят. Тормоз должен
  быть в решении: держи запас, если ведёшь, и трать всё, если проигрываешь.
  Пока бойцы были на нуле, каждая проверка стоимости в ИИ работала как запрет,
  и нижний в спине **ни разу** не пробовал уйти.
- **Пассивное «затягивается само» было сильнее работы атакующего.** Крип давал
  столько же очков в секунду, сколько всё, что делал душащий, — поэтому подача
  доводилась до конца сама, за девять секунд, кем бы она ни была поставлена.
- **Мини-игра сдачи была резонансом двух часов, а не борьбой.** Защита жалась по
  своему таймеру, направление менялось по своему; сетка по двум параметрам
  показала, что 0.2 секунды переворачивают чёрный пояс с 0 % законченных схваток
  на 95 %. Ворота и кулдауны только меняют одни часы на другие. Лечится не
  порогом, а рампой: побег **накапливается** за 0.9 с, и промах эту накопку
  тратит — тогда пояс покупает не скорость нажатий, а чтение.
- **Пережить подачу — значит выйти.** Защитника возвращало в ту же позицию,
  откуда его душили, так что выживание не покупало ничего: сверху тот же захват
  и тот же лучший ход. Теперь сорванный захват выводит его своим же ребром
  графа.
- **Захват отпускался раньше, чем рука переставала доставать.** Затухание
  начиналось на 0.9 длины руки — 47 см из 52, — а половина захватов в библиотеке
  сидит на 48–50: сиденье ремня, кросс-фейс, ладонь на дальнем бедре. Все они
  были вечно полуотпущены, а полуотпущенный захват — это рука, висящая рядом с
  тем, что она держит. По библиотеке: в среднем 4.7 см воздуха, худший случай
  59 см. Теперь держим всё, до чего рука достаёт, и отпускаем за несколько
  сантиметров дальше.
- **Захват за рукав целится в предплечье, которое само едет.** Решать захваты в
  один проход по списку — значит поймать рукав там, где он *был*: шесть захватов
  промахивались на 11–59 см по целям, до которых спокойно достают. Три прохода:
  второй перечитывает цели после того, как всё сдвинулось, третий сводит пары,
  которые держат рукава друг друга. Итог по библиотеке — 0.0 см среднего зазора.
- **Три ладони на одной точке — это не захват, а узел.** В спине оба держали
  одно и то же запястье, в рычаге локтя три руки сходились на четырёх
  сантиметрах — предплечьям было неоткуда прийти, кроме как сквозь друг друга,
  по 13 см. Разводится тем, что верно и в зале: защищающийся берётся за
  душащую руку, а рычаг держат вдоль руки — одна ладонь на запястье, вторая
  ниже по предплечью.
- **Захват, который есть в обеих позах, — это не кроссфейд.** `collect` брал
  больший из двух весов, и на середине любого блёнда вес схлопывался в 0.5.
  Полузахват не держит: рука сходит с лацкана ровно там, где проход самый
  плотный. Теперь веса складываются, если это один и тот же захват.
- **Инструмент, который переписывает файл целиком, стирает чужую половину.**
  `arc-solve` собирал `arcs.js` из шаблона, знающего только про `ARCS`, и молча
  уносил блок `VIAS`, который пишет `via-pick`. Три перехода лишились кривой.
- **`--fresh` вместе с `--only` стирал все дуги, кроме названных.** Худший момент
  в полёте прыгнул с 21 см до 29, и заметил это только `blend-check`. Случилось
  **дважды**: в первый раз «починка» оказалась комментарием над кодом, который
  как отбирал ключи после того, как выбросил тёплый старт для всех, так и
  продолжал. Во второй раз под нож попал файл, который перед этим час решался.
  Теперь порядок другой, а перед записью стоит сторож: прогон, который потерял
  бы хоть одну дугу, о которой его не просили, не пишет ничего.
- **Тринадцати проб на переход мало, и решатель это находит.** Самый глубокий
  момент перехода — часто одно пересечение шириной в пару сотых блёнда, и сетка
  такого шага через него перешагивает. Против сплошного прогона восемь переходов
  из сорока трёх занижались на 7 см и больше (`TURTLE>STANDING` показывал 7 см
  вместо 19), а худший момент во всём графе был 25 см при отчётных 19. Хуже
  того, `arc-solve` искал по **тем же** тринадцати точкам — и загонял столкновение
  в промежуток между ними: вторая петля маунта вышла из решателя на три
  сантиметра глубже, чем вошла, и оба инструмента считали её чистой. Сетки
  теперь разного размера нарочно: 25 у решателя, 41 у проверки.
- **Дуга, решённая под старую позу, хуже, чем никакой дуги.** Поправлять позу
  после `arc-solve` — значит оставить в файле кривую, которая тянет пару туда,
  где уже никого нет: у второй петли полугарда это давало 14 см на месте пяти.
  Пересолвливать надо ту же секунду, а не потом.
- **Проверку нельзя писать против абсолютного числа, если у концов свои числа.**
  Петля удержания судится не «меньше восьми сантиметров», а «не глубже, чем позы,
  между которыми она идёт»: у RNC предплечье поперёк горла и так читается как
  8 см, и так будет всегда.
- **Измеритель обязан сначала измерить себя.** `clip-check` печатает, насколько
  точно перенос чужой позы лёг на наш риг, и на первом же паке это спасло от
  ложного вердикта: 46 см ошибки, потому что у их скелета позвоночник длиннее
  ноги. Числа, зависящие от переноса, после этого помечены как оценка сверху, а
  приговор выносят меры, которым чужие пропорции безразличны.
- **Меш держится за бойца, а не за роль.** `A` и `B` в системе поз — это
  позиции (сверху/снизу), они меняются по нескольку раз за схватку. Пока меш был
  один, `gpuA/gpuB` по роли работали; со вторым персонажем тела менялись бы
  местами при каждом свипе. Теперь `gpuYou/gpuOpp` и поиск через `match.roleOf`.
- **Mixamo нумерует префикс рига.** У одного персонажа кости `mixamorig:Hips`, у
  другого — `mixamorig9:Hips`. Сравнение с буквальным префиксом находит ноль
  костей на втором же файле. `mixamo.mjs` экспортирует `bare()`.
- **«Тело — это то, что двигают кости кистей» — неверно для длинного рукава.**
  Рубашка с манжетой до запястья тоже привязана к кистям, и Ch31 запёкся с
  рубашкой, покрашенной как голая кожа. Тело — то, что тянется от пола до
  макушки; ничто из надетого так не делает.
- **Проверка не должна быть откалибрована по одному образцу.** «Ступня 17–34 см»
  означало «не короче, чем у первого бойца» — он проходил с запасом в миллиметр.
  Мерить надо относительно рига, который её двигает.
- **Складывать мир через `abs()` ради симметрии — значит отзеркалить надписи.**
  Четыре угловые эмблемы на мате берутся переносом через `sign()`, а не
  отражением: у отражённой эмблемы текст задом наперёд.
- **Атлас лежит «по-гэлевски», снизу вверх.** Инструмент, который читает его как
  обычную картинку, промахивается ячейкой и рисует план чужого мата. Шейдер при
  этом прав — ошибся инструмент.
- **Тёмный текст на мате не читается: зона боя тёмно-синяя.** Печатный файл клуба
  (чёрным по белому) — единственное, что нельзя перенести один в один.
- **Белая нашивка на белом кимоно исчезает.** Чёрное кольцо у эмблемы аффилиации
  должно стоять ровно по краю диска — на мате это ничего не меняет, на ги это
  вся разница между нашивкой и пятном.
- **Расписание от `currentTime` начинается в прошлом.** Контекст уже отрендерил
  блок-другой дальше той точки, которую читает главный поток, поэтому атака
  конверта попадает в уже смикшированный звук и наружу выходит один хвост. На
  телефоне это редкая мягкая нота; в headless-браузере, который рендерит
  длинными очередями, это 20–40 дБ, и синтезированный запасной звук выглядел
  неслышимым, не будучи им. Двадцать миллисекунд упреждения — и он вернулся.
- **«Звук есть» и «звук слышно» — разные проверки.** Щелчок интерфейса и звук
  сдачи выходили наружу и были на 3 дБ *под* залом, который играет под всем
  матчем; синтезированный хлопок ги — на 25 дБ под ним. Мерить громкость надо
  против зала, а не против нуля.
- **Анализатор, опрашиваемый по таймеру, теряет короткие звуки.** У headless нет
  звуковой карты, которая тянула бы граф ровно; колокол длиной в секунду
  успевает начаться и кончиться между двумя опросами. Одиннадцать событий из
  двенадцати числились тишиной. Отвод, который накапливает пик на каждом
  отрендеренном сэмпле, не теряет ничего.
- **Два живых AudioContext в одной вкладке врут друг про друга.** Второй прогон
  (с запрещённой загрузкой пака) шёл рядом с первым, который всё ещё мешал зал,
  и одни и те же числа расходились на двадцать децибел. Первый надо закрывать.
- **`aimBone` домножает, а не назначает.** Один перенос чужой позы на наш
  скелет — это правильно; второй на тот же экземпляр — уже нет. Цель всё так же
  достигается, но кватернион приходит к ней после лишней сотни умножений, а
  ненормированные произведения растут. Один `Skeleton` на пак из двадцати пяти
  клипов увёл ошибку переноса с ровных 36 см на первом клипе до 3.7 километра
  на двадцать пятом — плавно, клип за клипом, поэтому это и не читалось как
  сбой. `aimAll` теперь сбрасывает риг в покой перед каждым переносом.
- **Парность в имени файла — это не парность.** Пак может прислать
  `14_Mount_A.fbx` и `14_Mount_B.fbx`, где у обоих таз стоит в x = 0, z = 0.
  Тогда «пара» — это утверждение о синхронности во времени, а не о том, где два
  тела относительно друг друга. Ловится колонкой `jam`: ближайшие центры
  суставов сходятся в ноль.
- **Позицию делают конечности, и они могут спать.** В том же паке у маунта и
  закрытого гарда на ногах нет ни одной кривой: «сесть на соперника» выражено
  опусканием корня, а ноги остаются в стоячей позе, поэтому ступни уходят под
  мат ровно на столько, на сколько опущен таз. Ловится колонкой `still` —
  сколько прошла самая ленивая конечность относительно собственного таза.
- **Порог — это обрыв, и он всегда оказывается там, где садится типичный бой.**
  Семь побегов срывали подачу, и до седьмого не менялось ничего. Белый успевал
  восемь, чёрный одиннадцать — и на разнице в три побега одна сторона
  заканчивала 98 % своих захватов, другая 34 %. Тот же порог, размазанный в
  наклон (каждый побег сразу отнимает часть работы атакующего), вернул
  управляемость.
- **Если защита масштабируется поясом, а атака нет, пояса не ранжируются.**
  Белый попадал в такт вдвое реже чёрного и набирал почти столько же: промах
  стоил сотой доли счётчика и больше ничего. Лечится тем, что промах бьёт по
  тому же, по чему бьёт побег защиты, — по захвату.
- **Ворота на одном ходе — это подарок соседнему.** Как только вход в подачу
  потребовал подготовки, а четырёхочковый выход на спину рядом с ним остался
  бесплатным, фигура пошла не туда: рычаг из маунта ушёл в холод, спину стали
  забирать чаще, и её доля времени выросла вместо того, чтобы упасть. Ворота
  надо ставить на класс ходов, а не на один ход.
- **`ScriptProcessorNode` живёт в главном потоке и голодает за циклом WebGL.**
  Мерить звук на странице самой игры — значит мерить, сколько успел отрисовать
  рендер: один и тот же щелчок интерфейса показывал −21 dBFS в одном прогоне и
  −73 в следующем, а источник, подключённый прямо в пробник, показывал тишину.
  На пустой странице того же origin пробник откалиброван до десятой доли
  децибела. Два уровня в игре были подняты по показаниям голодающего пробника
  и на самом деле клиппировали: +1 dBFS.
- **Хвост предыдущего звука — это и есть «уровень зала».** Комнату мерили после
  двенадцати односэмплов, и последний из них (свист почти на секунду, четыре
  раза) ещё звенел: зал читался как −10 dBFS при настоящих −30, и каждое
  событие потом судили против зала, который громче правды на двадцать
  децибел.
- **Сравнить два кадра сложнее, чем кажется, и все три способа врут.** Байты
  PNG: изменение в один пиксель даёт 99 % различия. Пиксели: фигуры застыли, но
  кадр всё равно дрожит на доли пикселя, и сдвинувшийся край даёт сотню уровней
  там, где ничего не менялось. Среднее по кадру: сцена **светлеет по ходу
  прогона** — шесть одинаковых замеров дали 97.9, 97.9, 98.3, 99.1, 100.5,
  101.5, — поэтому любые два замера в разное время расходятся сильнее, чем
  измеряемое, а палиндром гасит только линейную часть этого. Каждая версия
  проверки проходила с полностью закомментированной фичей. Мерить надо там, где
  точно: усталость двигает скелет, скелет меряется в `pose-check`.
- **Проверка и список работ могут тянуть в разные стороны.** «Чёрный не хуже
  белого заканчивает» сравнивала чёрный-против-чёрного с белым-против-белого —
  два разных боя: белый заканчивает все свои, потому что напротив некому
  защищаться. А список работ хочет все эти числа вниз. Две меры сошлись в
  полосе шириной в несколько пунктов, и батарея начала падать на шуме. Ранг
  надо мерить против **одного и того же** соперника.
- **Проваленная подача обязана чего-то стоить.** Как только вход в подачу
  потребовал подготовки, а промах остался бесплатным, верхний просто пробовал
  снова — и спина забрала половину времени матча. Ровно тот же «зал ожидания»,
  что и от запрета душить при целой осанке, только с другой стороны.
- **`TRANSITIONS.find` — это всегда первое ребро в таблице.** Выход защитника
  из спины всегда оказывался черепахой, а из черепахи спину забирают обратно за
  4 очка: пережитое удушение кормило петлю из двух позиций. Выбирать надо
  случайно среди всех его побегов.
- **Подмена лица нарисованными чертами портит вылепленное лицо.** Где у меша есть
  настоящее лицо — шейдить и не трогать; рисовать глаза только там, где их нет.

### Из круга, где игру впервые измерили пальцем

- **Регулярка, собранная в шаблонной строке, — это не та регулярка.** В
  `` `\n  '${k}': \[[\s\S]*?\n  \],` `` внутри бэктиков `\[` и `\s` не
  экранирование, а буквы: получалось `[[sS]*?`, что не совпадает ни с одной
  дугой. `via-pick` бодро сообщал, что снял дуги у сменивших маршрут переходов,
  и не снимал ни одной. Молча — худшее из трёх возможных поведений.
- **Таблица, разобранная один раз на импорте, ломает всех, кто перебирает
  варианты.** `VIAS` парсились в план при загрузке модуля, а `via-pick` и
  `arc-solve` пробуют кандидата, присваивая в `VIAS`. Первая версия поиска по
  времени доложила, что «ни одна поза не помогает» нигде.
- **Маршрут, выбранный по прямой линии, — не обязательно лучший маршрут после
  дуги.** `via-pick` судит кандидатов без дуги, потому что дуга решена под
  старый путь; но и решённая под новый она иногда хуже. Из 43 пересчитанных
  переходов 20 остались на старой паре (маршрут + дуга), и это видно только
  когда меряешь пару целиком.
- **Форма поправки важнее её размера.** Расширение границ решателя (BEND 34 →
  48, LIMIT 0.16 → 0.20, больше костей) не сдвинуло семёрку ни на сантиметр.
  Третья доля — сдвинула: 20 → 10 см на самом плохом. У поправки не хватало не
  амплитуды, а формы.
- **Частота кадров, посчитанная из зажатого `dt`, не может упасть.** `frameAvg`
  кормили величиной, обрезанной на 50 мс, поэтому «fps» не опускался ниже
  двадцати, что бы ни происходило; под SwiftShader страница рисовала два кадра
  в секунду и сообщала двадцать один. Проверка в `smoke` не могла провалиться.
- **Первый кадр ждал того, кого на нём нет.** Соперник (768 КБ) грузился через
  `await` перед первым кадром — 11.3 с и 1.5 МБ на 1.5 Мбит/с. Он не нужен до
  гонга.
- **Подсказка защиты называла направление, и защита становилась бесплатной.**
  Окно 0.44 с — вдвое больше человеческой реакции; палец ответил 23 подсказки
  из 23, потом 35 из 35; оба матча кончились 2:0, и ни один из двоих не начал
  ни одной подачи. **Любая цена за рамку сплющивает лестницу поясов** — проверено
  дважды, выносливостью и осанкой: цена падает тяжелее на те пояса, которые
  защищаются чаще (белый против синего 45 % → 50 %, чёрный 90 % → 70 %). И
  **осанка сама по себе не работает как ворота**: она падает только тогда, когда
  по тебе проходят, а тот, кто отбивает всё, не пропускает ничего — на пороге 70
  арка не спряталась ни разу за 25 подсказок. Работает правило о положении, а не
  о ресурсе: **снизу не видно**. По десяти тысячам подсказок атакующий
  оказывается верхним в 72–84 % из них. ИИ это не трогает вовсе — он никогда не
  читал подсказку, он бросает свой `read`. Стало: 13 из 28, и палец впервые
  проиграл матч.
- **Метроном лечится неровностью, а не числом поз.** Петля удержания повторяла
  себя на 99 % ровно через пять секунд; третий вариант перенёс бы повтор на
  пятнадцать секунд и оставил бы те же 99 %.
- **`q.y` идёт вверх по ячейке атласа.** Надписи на бортах и на ленте вышли
  вверх ногами. И «читается снаружи» — правило для мата, а не для бортов:
  единственная камера в игре стоит внутри кольца.
- **Синтетическому `PointerEvent` нельзя захватить указатель.**
  `setPointerCapture` бросает исключение в середине обработчика, и весь ввод
  инструмента уходит в пустоту.
- **rAF в неактивной вкладке душат до четырёх кадров в секунду.** Измерять
  время реакции в таком браузере — значит измерять браузер:
  `--disable-renderer-backgrounding` и два соседних флага обязательны, а всё,
  что палец делает, считается в секундах **матча**, а не стены.

### Из круга, где взялись за картинку и движение

- **Судья мерил часы, а не путь.** `blend-check` брал сорок одну пробу
  равномерно по `t`, а поза шла как `smooth(t)`: пробы ложились густо по концам
  и редко в середине — ровно там, где переход и ломается. Стоило поменять кривую
  времени, и список работ вырос с одного перехода до одиннадцати, хотя ни одна
  поза и ни одна поправка не сдвинулись. Теперь у рига два входа: `applyAt(from,
  to, e)` — «где мы между двумя позами», и `apply(...)` — то же самое плюс
  кривая времени. Инструменты ходят по первому, игра по второму, а дуги
  считаются в параметре, которым их решали (`unsmooth(e)`), поэтому решённое
  остаётся на своём месте.
- **Слои, зависящие от предыдущего кадра, нельзя мерить пошагово.** Шаг и
  инерция смотрят на то, что было кадр назад, а инструмент прыгает по позе на
  несколько сантиметров за пробу. Обе живут за `rig.live`, инструменты их
  выключают, а **цена этого измеряется отдельно**: 0.1 см лишней глубины в
  удержании.
- **Оседание после броска стоит трёх сантиметров чужого тела.** Таз
  приземляющегося опускался на 3 см и возвращался — читается хорошо, но список
  работ вырос с одного перехода до семнадцати, а две петли стали «нельзя
  выпускать». Отменено; вес броска даёт кривая времени, а удар — импульс камеры,
  который и так был.
- **Пальцы вокруг ткани и кулак сквозь грудь для капсулы одно и то же.** Сжатие
  кисти на 34° по двум костям вывело восемь поз за черту. Шестнадцать градусов
  по одной кости говорят «держит» и не стоят ничего.
- **Складку нельзя измерить полосовым фильтром**: сгиб рукава и складка на нём
  живут на одном масштабе — около десяти пикселей. И «доля пикселей, близких к
  соседям» меряет высокие частоты, а складка — гладкий градиент: утроение
  глубины сдвинуло это число на один пункт из ста. Меряется только так же, как
  контакт — **тот же кадр с выключенной складкой, попиксельно**.
- **Экранная полоса «рядом с другим» — не то же самое, что контакт.** В маунте и
  в стороне она работает, в закрытом гарде и на спине — нет: двое могут
  перекрываться на экране не касаясь и касаться там, где силуэты не встречаются.
  Поэтому проверка идёт по медиане кадров, а не по худшему.

### Из круга, где игру разобрали по косякам

- **Защита решателя должна стеречь каждое число, по которому отгружаешь.**
  `arc-solve` — поиск со случайным началом, и перезапуск «на уточнение» умеет
  вернуть ответ хуже входного. Сторож писался четыре раза и каждый раз после
  того, как пропустил размен: сначала он сравнивал только полную цену — и через
  него прошёл ответ, который купил дешевизну глубиной; потом цену и глубину — и
  прошёл тот, что заплатил отрывом от мата, потому что отрыв **входит** в цену
  и достаточно большой выигрыш по глубине его окупает; потом добавился сгиб.
  Правило не «улучшить сумму», а **«не ухудшить ничего, что кто-нибудь меряет»**.
- **Мера, зависящая от крена, врёт — и пряталась в трёх местах сразу.** У
  `joint-check` в шапке написано, что из трёх попыток выжил угол между
  сегментами костей. Код так не делал: он проецировал сгиб на X плечевой кости,
  то есть на крен, которым не управляет ни поза, ни IK. `atan2` там схлопывается
  — любая рука, разведённая больше прямого угла и не в плоскости шарнира,
  читается как сложенная вдвое. 413 проб за границей превратились в 38, а три
  самые «страшные» оказались руками на 111, 113 и 101 градус. Тот же расчёт
  стоял в цене `arc-solve` (платил за выдуманное, не брал за настоящее) и он же
  раньше выгнал из `joint-check` меры `past` и `side`. **Если число зависит от
  крена — оно ничего не значит: у капсулы крена не видно.**
- **Захват — это объявление контакта, и более громкое, чем `hold`.** Послабление
  `pose-check` для «автор сам сказал, что они касаются» читало только `hold`.
  Но `grips` — прямое указание ригу: положи эту руку вот сюда, и IK кладёт.
  Точка `neck` стоит в 7 см перед костью шеи — это горло — и в 8 см от кости
  головы, а капсула головы там 10 см. Рука на горле оказывается на 8 см внутри
  черепа в тот же миг, как приходит, и **позой это не лечится**: полтора бюджета
  и прогон плеча по трём осям сдвинули число на ноль. Пары, которые вынуждает
  захват, ищутся так же, как их нашёл бы коллайдер — «в каких капсулах эта точка
  лежит», а не по имени кости, к которой точка привязана.
- **Список, вписанный руками, устаревает молча.** Проверка «у броска есть вес»
  меряла три перехода, вписанных в неё словами, и первым стоял
  `CLOSED_GUARD>MOUNT`. С появлением зеркал свип из закрытой гарды идёт в
  `MOUNT_X`, а вписанная пара осталась слерпом без арки, на который никто не
  смотрит; она давала пик на 58 % и валила проверку. Теперь список берётся из
  графа через тот же `visualTo`, которым блендит риг: 55 переходов вместо трёх и
  устареть больше нечему.
- **Измеритель, которого нет в батарее, не измеряет ничего.** `joint-check`
  написали, им нашли 85 суставов вне человеческого диапазона — и в `verify.mjs`
  не добавили. Поэтому когда мера внутри него сломалась, этого никто не увидел.

### Из круга, где выяснилось, что в игру нельзя играть

- **Баланс, измеренный AI против AI, ничего не говорит про человека.**
  `sim-check` гонял четыреста матчей и показывал ровную лестницу поясов, пока
  живой игрок проигрывал двадцать матчей подряд белому поясу. Причина в том,
  **что AI не читает подсказку на экране вообще**: он бросает кубик по
  `level.read`. Значит, любое число про защиту, измеренное в sim-check, — это
  число про кубик, а не про окно, руку и глаз. Половина игры, в которую играет
  человек, не измерялась ничем, кроме `thumb.mjs`, который играет в реальном
  времени и потому отвечает на «успевает ли рука», но не на «кто выигрывает из
  двухсот».
- **Одна константа держала всю игру, и её никто не мерил рукой.** Окно ответа на
  атаку было ровно 0.44 с на все переходы. Измерено `human-check.mjs` (быстрый
  headless-двойник `thumb.mjs`: та же опоздалость, тысяча матчей в минуту, читает
  только то, что рисует HUD) против белого пояса:

  | рука | отбито атак | побед |
  |---|---|---|
  | 320 мс | 65 % | 63 % |
  | 450 мс | 21 % | 23 % |
  | 600 мс | **1 %** | 15 % |

  320 мс — это элитная реакция на сигнал, который ещё надо прочитать и выбрать
  из него направление. Игрок с телефоном смотрит на бойцов, а не на кольцо, и
  живёт в 500–600. То есть защищаться было физически нельзя, при этом очки
  игрок набирал (6.3 своих против 10.3 чужих) — он проигрывал ровно ту половину,
  которую ему не давали играть.
- **Починка — не большая константа, а правило.** Окно теперь — собственный замах
  атаки: `tr.time * 0.9`, от 0.45 до 0.95 с. Быстрый свип по-прежнему даёт
  меньше времени, чем проход, — этим он и быстр. Свип по константе показал, что
  дальше 0.9 с ничего не меняется: попытка уже приземлилась. Лестница поясов
  (sim-check) не поехала, `escape-check` не поехал.
- **Браузерный измеритель на программном растеризаторе даёт скидку, которой не
  просили.** `thumb.mjs` играет на реальной странице, страница идёт 7 fps, часы
  матча — 0.35 реального времени. Задержки руки считаются в секундах матча, так
  что рука 220 мс + 150 мс на поворот головы обходится игре примерно в 130 мс —
  втрое дешевле правды. Инструмент сам печатает эту оговорку строкой выше своих
  чисел, и её надо читать. Поэтому цена внимания живёт теперь и в
  `human-check.mjs`, где часы матча — это цикл, а не кадры.
### Из круга, где посмотрели на движение между кадрами

- **Ни один измеритель не смотрел, где сустав был на соседнем кадре.**
  `pose-check` меряет позы, `blend-check` — путь между ними, `flow-check`
  спрашивает, не прыгает ли параметр бленда. Поэтому сустав мог дрожать на месте
  весь матч или щёлкнуть на десять сантиметров за шестидесятую долю секунды, и
  батарея оставалась зелёной. `shake-check` гонит настоящий риг на 60 кадрах в
  секунду по настоящим матчам и смотрит мировые позиции всех 26 костей у обоих.
- **Дыхание сбрасывало себе фазу шестьдесят раз в секунду.** Было
  `Math.sin(T * rate)`, где `rate` зависит от усилия и усталости, а усталость
  меняется каждый кадр. Значит менялась **фаза**, а не скорость: на третьей
  минуте `T`≈180, и тысячная доля изменения частоты двигает аргумент синуса на
  пятую радиана. На дыхании висят грудь, спина и шея, а на груди — обе руки.
  Выключение дыхания роняло 90-й процентиль ускорения сустава со 105 м/с² до 14;
  выключение всего тремора усилия не меняло **ничего**. Вывод общий: **любой
  `sin(T * f(t))` — это баг, фазу надо интегрировать.**
- **Вес захвата — это расстояние, на которое кисть оттянута от позы.** Значит
  менять вес — значит двигать кисть, а менять его за кадр — телепортировать её.
  Два места так и делали: `fit` отпускает захват на последних пяти сантиметрах
  вылета руки (окно в **расстоянии**, а расстояние до точки на чужом теле в
  переходе меняется на 2–5 см за кадр), и захват слабее 2 % просто пропускался.
  В каждом переходе игры был скачок 30–67 см за кадр, и всегда кистью.
- **Что попробовали и выбросили — оба раза по измерению.** (1) Общий поглотитель
  рывков: любой скачок снимается в суставном пространстве и возвращается за
  треть секунды. В изоляции чинит начисто (13 см → 0), в матче добавляет рывков
  больше, чем убирает, — потому что совпадение только по позиции **останавливает
  тело на кадр**, а это свой собственный разрыв; попытка совпасть ещё и по
  скорости через кватернионную экстраполяцию взрывается (1.9e40). (2)
  Пространственный кроссфейд между двумя целями захвата: в равномерном проходе
  убирает телепорт 57 см на середине `BACK>RNC`, но в живой игре ограничитель
  скорости цели уже это закрывает, зато рикошетом складывает чужой локоть на
  173°. **Обе идеи правильные по форме и обе не окупились — это и есть причина
  мерить до, а не после.**
- **Если инструмент обнуляет часы рига, он должен обнулить и фазу дыхания.**
  `rig.time = 0` стоял в пяти инструментах, чтобы мерить позу, а не момент. С
  собственной фазой у дыхания этого мало: 38-я поза в прогоне меряется с двумя
  третями радиана дыхания, которых не было у первой, и черепаха отчиталась о 8 см
  руки внутри руки. Теперь `rig.rewind()` обнуляет оба.
- **Камера кадрировала по объективу и не знала, кого снимает.** Измерено
  `camera-check`: пара занимала 79 % высоты кадра в среднем, была выше кадра в
  каждом шестом кадре, а внутри болевого — 113 % и **срез на каждом кадре**. Из
  кадра вылетали кисти, пальцы и предплечья, то есть сам приём. Теперь в камеру
  передаётся `spread` — насколько пара расходится от точки прицела, — и объектив
  только **открывается**, никогда не поджимается: рисунок каждого плана остался
  свой, а разрезать бой пополам камера больше не может. 79 % → 51 %, срез
  39.7 % → 0.2 %.

- **Всё, что играет в эту игру, свайпает. Человек — жмёт.** Кольцо нарисовано
  четырьмя кружками с подписью и ценой на каждом. Это выглядит как четыре
  кнопки. Кнопками они не были: нажатие принимал только свайп, а тап по правой
  половине — это борьба за захват. То есть игрок, который тыкал в кнопку «+4»,
  всю игру дрался за воротник и не сделал ни одного хода. Ноль очков за двадцать
  матчей — не баланс, а это.

  Почему батарея этого не видела: `thumb.mjs` шлёт pointerdown → pointermove →
  pointerup, `human-check` зовёт `match.input` напрямую, `flow-check` смотрит на
  граф. **Ни один измеритель не трогал экран так, как трогает его палец.** Урок
  общий: если инструмент воспроизводит замысел разработчика, он не проверяет
  интерфейс — он проверяет себя. Теперь есть `ring-check` (геометрия попадания
  на семи экранах) и `tap-check` (настоящий PointerEvent на настоящей странице
  до `match.input`).
- **Две строки на одной высоте — это одна строка.** На титульном экране правило
  «очки идут за +N и только если удержать три секунды» рисовалось на `base + 32`,
  а строка с поясом — на `base + 31`. Единственное объяснение правил в игре было
  нечитаемо, и никто не смотрел на титульный экран глазами после того, как
  строку туда добавили.
- **Дырка в счёте нашлась не глазами, а требованием «у каждого прихода есть
  конец».** Три места гасили начатые три секунды молча: уход в позицию без
  очков, вход в сдачу и судейский подъём в стойку. Преимущество, которое правила
  дают за сорванное удержание, в этих трёх случаях не давали никогда. Аудит
  `tape-check` («каждый приход кончается очками или преимуществом») выдал восемь
  матчей из шестидесяти, и только после этого стало видно, что `hold` затирался
  в четырёх местах, а гасился по правилам в одном.

Одна оговорка про батарею: в `sim-check` проверка «каждая позиция достижима»

намеренно, иначе он проверяет одну-единственную последовательность. Зерно
теперь **печатается** в строке «every match reaches an end», и упавший прогон
повторяется целиком: `node bjj/tools/sim-check.mjs 400 --seed <то самое>`. Весь
бой берёт числа из одного потока (`src/game/rng.js`), и `sim-check` проверяет
это последним пунктом: один и тот же посев — один и тот же матч, позиция в
позицию и очко в очко.

## 9. Ограничения среды

- `drive.google.com`, `mixamo.com` и вообще все домены Google **заблокированы**
  сетевой политикой машины (`CONNECT tunnel failed, 403`). Открыт GitHub.
  Файлы приходят либо загрузкой прямо в чат, либо через GitHub Releases (2 ГБ через
  браузер; вкладка «Add file → Upload files» — только 25 МБ).
- Браузерные инструменты требуют `CHROME_PATH=/opt/pw-browsers/chromium-1194/chrome-linux/chrome`
  и поднятого `python3 -m http.server 8099` в корне репозитория.
- **Полный прогон `arc-solve` не переживает перезапуск контейнера** — час работы
  и одна запись в конце. Гонять кусками по пять переходов (`--only`), каждый
  пишет `arcs.js` сам, и запускать отцеплённо (`setsid nohup`): сторож,
  повешенный на такой прогон, при своём таймауте утаскивает его с собой.
  И `pgrep -f arc-solve` **находит собственную командную строку** того скрипта,
  который им ждёт освобождения файла: ожидание становится вечным.
